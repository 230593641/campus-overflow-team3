# 任务领取规则

## 每天的动作（固定 6 步）

1. 打开看板，看「本周待领取」列；
2. 选一个前置任务已完成的 Issue，评论「领取」，把自己设为 Assignee；
3. 把卡片拖到「进行中」；
4. 建分支：`git checkout -b feature/<issue编号>-<简短描述>`；
5. 写代码，跑 Issue 里的验收命令；
6. 提 PR（自动带模板），关联 Issue（写 `Closes #<编号>`），等评审。

## 四条纪律

- **WIP 限制**：每人同时最多 2 个「进行中」任务；
- **卡住 4 小时**：在 Issue 评论阻塞原因并 @SM，不许闷头死磕；
- **不跨任务改文件**：发现别的问题，开新 Issue，不要顺手改；
- **每天站会前更新看板**，否则视为未推进。

## 任务与 Issue 对应

- 32 个开发任务总表见 [107任务拆解表](107任务拆解表.md)；
- 每个任务 = 一个文件 = 一个 PR；
- 只做前置任务已完成的 Issue；同一文件不要两人同时改。
