# 测试策略

> 测试金字塔：上层少而慢，下层多而快。本项目以领域单元测试为重心。

| 层级 | 工具 | 覆盖对象 | 运行命令 | 目标 |
| --- | --- | --- | --- | --- |
| 单元测试 | JUnit 5 + Mockito | 领域聚合、值对象 | `mvn test -pl <module>` | 领域覆盖率 ≥70%，核心聚合 ≥90% |
| 应用层测试 | JUnit 5 + 假实现 | 用例编排、事件发布 | `mvn test -pl co-qa/co-qa-application` | 关键用例全覆盖 |
| 集成测试 | Testcontainers + MySQL/Redis | Controller→Service→Repository | `mvn verify` | 端到端链路通过 |
| 契约测试 | OpenAPI 校验（可选 Pact） | 前后端接口 | `npm run typecheck` + 手工核对 | S2 起每个接口有契约 |
| 端到端 | Playwright（S4 可选） | 关键用户旅程 | `npx playwright test` | 3 条主链路 |
| 架构测试 | ArchUnit | 分层与依赖 | `mvn test -pl co-bootstrap -Dtest=ArchitectureTest` | 全过 |

## 原则

1. 红-绿-重构：先看测试规格（`src/test`），再实现；
2. 不改已有测试断言；新功能必须补测试；
3. 领域层不依赖框架，测试不启 Spring 上下文；
4. 异步声誉结算用幂等消费，对账测试覆盖冻结-扣减-退还守恒；
5. CI 中 `ci.yml` 全量允许按 Sprint 递减地红，`skeleton-check` 必须绿。
