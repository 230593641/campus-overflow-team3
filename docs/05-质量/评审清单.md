# PR 评审清单

> 评审者按六类逐项勾选；任何一类有未解决问题，PR 不予 approve。

## 正确性
- [ ] 需求/验收标准是否被完整覆盖
- [ ] 边界条件（空、null、负数、超长）是否处理
- [ ] 并发场景是否安全

## 可读性
- [ ] 命名是否准确、无缩写
- [ ] 函数是否 <30 行、嵌套 <3 层
- [ ] 注释是否解释"为什么"

## 可测试性
- [ ] 核心逻辑是否有单元测试
- [ ] 依赖是否注入而非硬编码
- [ ] 是否存在无效断言

## 安全
- [ ] 是否有 SQL 注入 / XSS / CSRF 风险
- [ ] 密码、Token、Secret 是否硬编码
- [ ] 日志是否泄露敏感信息

## 性能
- [ ] 是否有 N+1 查询
- [ ] 热点路径是否有不必要对象创建
- [ ] 缓存是否考虑失效

## 风格
- [ ] Checkstyle / ESLint 是否通过
- [ ] Commit message 是否符合规范
